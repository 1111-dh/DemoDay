# capture/ — B 담당 (Playwright 캡처)

- CLI: `pnpm --filter @demoday/capture capture <scenario.json> <runDir>`. 진입점은 `src/capture.ts`.
- 입력 `Scenario`, 출력 `<runDir>/capture.json`(`Capture`)과 `<runDir>/shots/<stepId>.png`. 타입은 `@demoday/contracts`.
- viewport는 1280x720 고정이다. 클릭 좌표는 이 viewport 기준 px이고, 렌더러가 줌·커서에 그대로 쓴다.
- 클릭 좌표는 요소 bounding box의 중심으로 기록한다.
- 셀렉터를 못 찾거나 타임아웃(단계당 5초)이 나도 **멈추지 않는다**. 현재 화면을 찍고 `status: "fallback"`으로 기록한 뒤 다음 단계로 간다. `goto` 응답이 400 이상(없는 페이지)이어도 fallback이다. 단계 뒤 3초가 지나도 로딩 뼈대(`skeleton`·`animate-pulse`·`shimmer`·`aria-busy`)가 화면에 남거나, `goto`가 로그인 페이지(`/login`·`/signin`)로 보내지면 보여줄 내용이 없으므로 fallback이다(scene에서 빠진다). 스크린샷까지 실패하면 빈 화면을 쓰고 fallback으로 둔다.
- 종료 코드: 0이면 capture.json 생성(fallback 포함), 0이 아니면 생성 실패.
- 개발 중에는 `contracts/fixtures/scenario.json`이나 직접 쓴 scenario로 실제 배포 URL에 돌려 본다. 결과는 `make validate FILES=<runDir>/capture.json`으로 확인한다.
- 로그인: scenario에 `auth.steps`가 있으면 본 `steps` 전에 **녹화하지 않는 별도 컨텍스트**에서 실행하고, 로그인 상태(쿠키·localStorage·IndexedDB·sessionStorage)만 녹화 컨텍스트로 넘긴다. 마지막 로그인 클릭 뒤에는 페이지가 넘어갈 때까지(최대 8초) 기다린다(로그인 요청이 끊기지 않게). 스크린샷·`capture.json`에 넣지 않고, 값·URL을 로그에 쓰지 않는다. 실패해도 멈추지 않고 본 단계로 간다. 예시: `contracts/fixtures/scenario.auth.json`.
- auth(로그인) 값은 영상·스크린샷·로그·`capture.json` 어디에도 남기지 않는다. 일반 단계 입력값은 가리지 않는다(LLM이 만든 데모 문구이고, 입력 장면이 움직임의 핵심이라서).
- 녹화: 본 단계를 1280x720로 녹화해 `<runDir>/capture.webm` + `capture.video`, 단계별 `clip`(녹화 시작 기준 ms)을 기록한다. `goto` clip은 페이지 load 뒤부터 시작하고(로딩 중 빈 화면 제외), 단계 뒤 결과 화면을 1.5초 더 녹화해 clip에 넣고, 앞 여유(0.3초)는 앞 clip 끝과 겹치지 않게 자른다. 녹화 안에서 로그인하지 않는다. 녹화가 실패하면(ffmpeg 없음 포함) `video`·`clip` 없이 정지 화면만 낸다.
- click·type 단계는 `clip.startMs + 0.8초`에 클릭한다(type은 그다음 입력). 렌더 ScreenScene의 커서 박자(0.1~0.8초 이동, 0.8초 클릭)와 같으므로 한쪽을 바꾸면 둘 다 바꾼다. `type`은 한 글자씩(60ms), 스크롤은 나눠서 움직인다.
- **에이전트 모드**(#53, `--agent` 또는 `CAPTURE_MODE=agent`): 첫 단계 `goto /` 뒤로는 시나리오 대신 에이전트가 고른 동작을 실행한다(`src/agent.ts`). 화면 안의 클릭·입력 가능한 요소(가운데 점이 실제로 보이는 것만, 최대 60개)에 번호(`data-demoday-id`)를 붙여 관찰 JSON 한 줄을 에이전트 프로세스(`DEMODAY_AGENT_CMD`, 기본 `uv run --project backend python -m app.agent`) stdin 으로 보내고, stdout 한 줄로 동작을 받는다. 관찰은 `agent/<n>.json`·`agent/<n>.png`에 남는다. 실행·녹화·clip·빈 화면 감지는 시나리오 모드와 같다. 최대 10동작, 같은 동작 반복·로그인 화면이면 멈추고, 다른 사이트로 나가면 되돌린다. 끝나면 실제로 한 동작을 다시 찾을 수 있는 셀렉터로 `scenario.json`에 덮어쓰고(에이전트 없이 재생 가능 — 시연 캐시용), 원래 시나리오는 처음 한 번 `scenario.plan.json`으로 남긴다. 에이전트를 못 띄우거나 첫 동작부터 실패하면 그 시나리오 단계로 대신한다. A 없이 개발할 때는 `--agent-script <actions.json>`(동작 목록, `id` 대신 `name`으로 요소 지정 가능). 셀렉터: 입력칸은 속성(`#id` → `[name]` → `[placeholder]`), 그 외는 접근성 이름 앞부분 정규식(`role=link[name=/^…/]`, 공백·장식 화살표는 있어도 없어도 됨 — `role=`의 `name="…"`은 정확히 일치라 innerText와 공백이 다르면 못 찾는다). 둘 다 `>> visible=true >> nth=0`(숨은 모바일 메뉴의 같은 이름 제외). 기록 전에 그 셀렉터가 실제로 같은 요소를 찾는지 확인하고, 아니면(aria-hidden 평점·aria-label 등으로 관찰 이름과 접근성 이름이 다름) Playwright가 계산한 role·이름(`ariaSnapshot`, 앞 40자 정규식)으로 바꾼다. 둘 다 안 되면 경고만 남긴다. 입력칸이 아닌 요소에 온 `type`은 거절한다. 자체 검사: `pnpm --filter @demoday/capture exec tsx src/agent.check.ts`(실제 페이지에서 추출 → 기록 → 다시 찾기).
- **Flutter web**(`flutter-view`·`flt-glass-pane` 요소가 있는 페이지)은 canvas라 그대로는 셀렉터가 없다. 페이지를 연 뒤 `document.querySelector('flt-semantics-placeholder')?.click()`으로 semantics를 켜면 `role=button[name="…"]`·`role=textbox[name="…"]` 셀렉터가 동작한다(A의 scenario가 이 형식을 쓴다). 해시 URL(`/#/x`)도 그대로 `baseUrl + path`로 연다.
