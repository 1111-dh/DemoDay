# 영상 품질 끌어올리기 — 화면 녹화·이야기 흐름·로그인·사용자 프롬프트

날짜: 2026-11-22 · 마감 11/24(화) 11시 제출

## 왜

"Claude한테 직접 시켜서 만든 영상"보다 나아야 우리 서비스가 경쟁력이 있다. 지금 자동 생성 영상(예: `runs/1122-214617/preview.mp4`)은 기준선에 한참 못 미친다. 기준선은 managers-manager(ktc4-kyungpook-3) README 영상(Claude로 제작, 3분 45초, 1280×720, 음악 포함)이다.

두 영상을 같은 간격으로 프레임을 뽑아 비교한 차이:

| | 기준 영상 | 지금 우리 영상 |
|---|---|---|
| 흐름 | 불편함(문제) → 해결 기능 → 동작 원리 → 정리 | 화면을 순서대로 나열 |
| 자막 | 이점을 말하는 문장, 핵심어 주황 강조 ("**녹음 파일**로 올립니다") | 화면 이름표 ("캘린더 화면") |
| 화면 | 실제 입력·스크롤 움직임, 말풍선·체크 강조 표시 | 정지 화면 1장을 6~7초, 빈 칸으로 줌 |
| 디자인 | 밝은 배경 위 브라우저 카드, 장 구분 카드("07 이렇게 동작합니다"), 끝 흐름도 | 남색 타이틀과 꽉 찬 스크린샷이 따로 놂, 아키텍처 장면은 "Flutter" 글자 하나 |
| 기타 | 배경음악 | 무음, 에러 화면이 그대로 들어감 |

## 목표

- 정지 화면 대신 **실제 브라우저 세션 녹화**에서 단계별 구간을 잘라 쓴다(입력은 한 글자씩, 스크롤은 부드럽게).
- 자막과 장면 순서를 **문제 → 해결 → 정리** 이야기로 만들고, 핵심어를 강조한다.
- 브라우저 카드 프레임, 장 구분 카드, 배경음악으로 보이는 인상을 기준 영상에 가깝게 한다.
- 사용자가 **테스트 계정 아이디·비밀번호**를 넣으면 로그인한 상태로 캡처한다.
- 사용자가 제작 전에 **짧은 프롬프트**를 쓸 수 있다. 프롬프트는 화면 순서(시나리오), 자막 말투, 강조할 부분에 반영된다.

## 하지 않는 것 (non-goals)

- 기준 영상처럼 손으로 그린 일러스트·문제 상황 연출(휴대폰 녹음 장면 등). 문제 제시는 장 구분 카드의 문장으로 한다.
- 말풍선·체크 같은 화면 위 강조 표시(callout). 시간이 남으면 다음 단계로 제안한다.
- 만든 뒤 말로 고치는 "자연어 수정"(MVP 제외 그대로). 제작 전 프롬프트는 생성 입력이라 이와 다르다 — `AGENTS.md` 범위 줄에 이 구분을 적는다.
- 로그인 과정의 **녹화**. 로그인 화면은 넣더라도 정지 화면(입력칸 가림)으로만 보여준다(아래 "로그인 장면").
- 내레이션(TTS).

## 실패로 보는 것 (anti-goals)

- 녹화 때문에 **영상이 안 나오는 경우**. 녹화가 실패하면 지금처럼 정지 화면으로 반드시 나와야 한다.
- 로그인 비밀번호·secret URL이 **영상·스크린샷·로그·캐시**에 남는 것.
- 에러 화면("프로필이 아직 생성되지 않았습니다" 같은)이 영상에 들어가는 것.

## 제약

- 마감까지 약 1.5일. 순서를 잘못 잡으면 아무것도 못 건진다 → 아래 "단계" 참고.
- 폴더 담당: A `backend/`, B `capture/`·`render/`, C `web/`·아키텍처 장면. 남의 폴더는 그 사람이 고친다.
- 계약(`contracts/*.schema.json`)은 팀 합의 후에만 바꾼다. 아래 변경은 모두 optional이라 하위 호환된다.

## 접근 방식 (검토한 것)

| 안 | 내용 | 결론 |
|---|---|---|
| A안 | 이야기·자막만 개선(A 단독, 계약 변경 없음) | 품질은 오르지만 정지 화면 그대로 |
| B안 | A안 + 디자인(카드 프레임·강조 자막·장 구분) | 인상은 크게 바뀌지만 움직임 없음 |
| **C안 (선택)** | B안 + 세션 녹화로 실제 움직임 | 기준 영상에 가장 가깝다. 대신 캡처·계약·렌더가 다 바뀐다 |

사용자가 C안을 골랐다. 작업은 **나눠서** 한다(A: 이야기·로그인·프롬프트·장면 매핑·계약 제안, B: 녹화·렌더, C: 입력 화면).

- **이 문서로 세울 구현 계획은 A(backend) 몫만** 다룬다. 남의 폴더(`capture/`·`render/`·`web/`)는 고치지 않는다.
- B 몫과 계약 변경은 **GitHub 이슈**로 넘긴다(`gh issue create`, 올리기 전 사용자 확인).
- C는 아직 작업을 시작하지 않았으므로 이슈 대신 **`web/AGENTS.md`**에 C 몫을 적어 둔다.

## 설계

### 단계 (안전망 순서)

1. **A 단독(계약 변경 없음)** — 이야기 흐름, 자막 강조 문장, 에러 화면 거르기, 로그인 입력, 사용자 프롬프트. 이것만으로 B안 직전 수준이 확보된다.
2. **계약 합의** — 아래 optional 필드 추가. 스키마 수정 → `make gen` → fixtures 갱신 → `make check`.
3. **B 녹화·렌더, C 입력 화면** — 동시에 진행. A는 scene.py에서 새 필드를 채운다.

2·3단계가 마감 전에 불안정하면 녹화 없이(1단계 결과 + 정지 화면) 제출한다.

### 계약 변경 (optional, 하위 호환)

`capture.schema.json`
- `Capture.video?: string` — 세션 녹화 파일, run 디렉터리 기준 상대경로(예: `capture.webm`). 녹화 실패 시 생략.
- `Capture.login?: {images: string[]}` — 로그인 장면용 정지 화면(run 디렉터리 기준, 예: `shots/login-1.png`, `shots/login-2.png`). 입력칸은 가린 상태. 낮은 우선순위 — 없으면 로그인 장면 없이 간다.
- `Shot.clip?: {startMs: int, endMs: int}` — 이 단계가 `video`에서 차지하는 구간(녹화 시작 기준 ms). 동작 시작 ~ 화면 안정 직후.

`scene.schema.json`
- `ScreenScene.video?: {src: string, startMs: int, endMs: int}` — 있으면 이 구간을 재생하고, `image`는 대체 화면(poster)으로 쓴다.
- `ScreenScene.highlight?: string[]` — `caption` 안에서 강조할 단어.
- `TitleScene.kicker?: string` — 제목 위 작은 라벨(예: `"01"`, `"문제"`). 있으면 장 구분 카드로 그린다. 새 scene type을 추가하지 않고 장 구분을 표현하려고 TitleScene을 확장한다.

### A — backend (이 문서 작성자 담당)

**로그인 입력**
- `POST /api/runs` 요청에 `login?: {username, password}` 추가(API 표는 `backend/AGENTS.md`).
- A가 레포 분석 결과의 로그인 페이지(경로에 `login`/`signin` 등, 입력칸 2개 이상 + 버튼)에서 `scenario.auth.steps`를 만든다: `goto 로그인 페이지 → type 아이디 → type 비밀번호 → click 로그인 버튼`.
- 비밀번호는 기존 auth 규칙 그대로: run 디렉터리 scenario.json에만 저장, 응답에서는 `***`, LLM·캐시에 넣지 않는다.
- 아이디·비번 입력칸을 못 찾으면(예: 안정형처럼 소셜 로그인만 있는 앱) 400으로 알려준다. 대체 수단으로 기존 `auth`(직접 만든 로그인 단계 — 예: 데모 로그인 URL)를 그대로 받는다.
- CLI·e2e: `--login-user/--login-pass` 대신 기존 `--auth <file>`를 계속 쓴다(파일에 아이디·비번 단계를 적는다).

**사용자 프롬프트**
- `POST /api/runs` 요청에 `prompt?: string`(최대 500자) 추가. run 상태(`runs.write_status`)에 저장해 이후 `build`의 scene 생성에도 쓴다.
- 시나리오 LLM에는 "화면 순서·보여줄 기능" 지시로, scene LLM에는 "자막 말투·강조할 부분" 지시로 넣는다. 사용자 입력은 시스템 지시가 아니라 **참고 요청**으로 감싸서 넣는다(계약·스키마 규칙을 뒤집지 못하게).
- 시나리오 캐시 키에 프롬프트 해시를 포함한다(`scenario__{owner}__{repo}__{sha}__{url키}[__{prompt키}].json`). 프롬프트가 없으면 지금 키와 같아서 `make warm` 캐시가 그대로 쓰인다.
- CLI: `analyze --prompt "…"`, `scene`은 run 상태에서 읽는다. e2e: `PROMPT=…`.

**이야기 흐름 (prompts/scenario.md, prompts/scene.md, scene.py)**
- 시나리오: README의 문제·해결 설명을 근거로, 핵심 기능을 보여주는 순서로 단계를 고른다. **흐름 중간의 결과 화면(`result`·`loading`·`detail`·`success` 등 앞 단계 상태가 필요한 화면)으로 바로 goto하지 않는다** — 클릭으로 들어가는 흐름은 클릭으로 따라가거나 거기서 끝낸다.
- scene: 오프닝 TitleScene(서비스 이름 + 한 줄 가치) → 장 구분 TitleScene(`kicker`)으로 "문제" 한 문장 → 기능 화면들 → 끝 TitleScene(정리 한 문장). 자막은 화면 이름이 아니라 **사용자가 얻는 것**을 말하고, 핵심어 1~2개를 `highlight`로 준다(계약 합의 전에는 `highlight` 없이 문장만).
- 자막은 지금 규칙(df48d34: 화면에 없는 내용을 지어내지 않기)을 유지한다. 근거는 README와 그 화면의 요소 문구.
- 지금 `RepoFacts`는 README 첫 문단(300자)만 담는다. 문제·해결 문장의 근거가 되도록 README 본문 앞부분(제목·소개·주요 기능 절, 상한 약 2,000자)을 facts에 추가하고 두 LLM 입력에 넣는다. *(작성자 판단)*
- README에 문제 설명이 없으면 "문제" 장 구분 카드는 **넣지 않는다**(지어내지 않기 규칙 우선). 그때 구조는 오프닝 → 기능 → 정리. *(작성자 판단)*

**에러 화면 거르기** *(작성자 판단 — 단순 규칙)*
- `status: "fallback"` 단계 자체는 지금처럼 남기고 길이만 줄인다.
- fallback이 **연속**되면 첫 번째만 남기고 나머지는 장면에서 뺀다(한 번 실패 뒤 이어지는 단계가 보통 같은 화면이라서). 성공 단계는 그 뒤에 와도 남긴다.
- 이 거르기는 scene LLM 호출 **전에** 한다(자막·가중치 개수 = 남은 shot 수).
- 화면 내용(에러 문구) 판별은 범위 밖 — 시나리오 규칙(위)으로 예방한다.

**장면 매핑 (계약 합의 후)**
- `scene.py`: `capture.video`가 있고 shot에 `clip`이 있으면 ScreenScene에 `video: {src, startMs, endMs}`를 넣는다. `durationSec`은 구간 길이를 기본으로 하되 전체 `totalSec`에 맞춰 비율 조정(렌더가 재생 속도로 맞춘다 — B 참고).
- `capture.login.images`가 있으면 오프닝 TitleScene 바로 뒤에 ScreenScene(이미지만, 짧게)으로 넣고 자막은 "테스트 계정으로 로그인" 류의 고정 문구. *(낮은 우선순위)*

**규칙 문서**
- 루트 `AGENTS.md` MVP 제외 목록: "로그인 화면을 장면으로 만드는 것" → **"로그인 과정 녹화·입력값이 보이는 로그인 장면"**으로 바꾸고, "로그인 장면은 입력칸을 가린 정지 화면으로만(낮은 우선순위)"을 적는다. "자연어 수정"에는 "(제작 전 프롬프트는 허용)"을 덧붙인다.
- `backend/AGENTS.md` API 표에 `login`, `prompt`를 추가한다.

### B — capture·render (이슈로 전달)

**녹화 (capture/src/capture.ts)**
- auth 단계는 **녹화하지 않는 컨텍스트**에서 실행하고, `context.storageState()`로 로그인 상태를 뽑아 **녹화용 새 컨텍스트**(`recordVideo: {dir, size: 1280×720}`)에 넘긴다. 비밀번호 입력·secret URL이 녹화에 남지 않게 하는 핵심 장치다.
  - `storageState`는 쿠키·localStorage만 옮긴다. sessionStorage도 함께 옮긴다(로그인 컨텍스트에서 읽어 녹화 컨텍스트에 `addInitScript`로 복원). *(작성자 판단)*
  - 시연 두 앱(managers-manager = React, 안정형 = Flutter)에서 녹화 컨텍스트가 로그인 상태로 시작하는지 확인한다. 그래도 로그아웃 상태면 **녹화 없이** 지금 방식(같은 컨텍스트, 정지 화면)으로 대체한다 — 녹화 컨텍스트 안에서 로그인하는 방식은 쓰지 않는다(녹화 파일에 비밀번호 입력이 남는다).
- 녹화 시작 시각을 0으로 단계별 `clip.startMs/endMs`를 기록한다(지금 `atMs` 기준점과 맞춘다).
- 움직임: `type`은 `pressSequentially`(글자당 ~60ms), 스크롤은 여러 번 나눈 `mouse.wheel`. 클릭 전 마우스를 요소 중심으로 이동(커서 자체는 렌더가 그린다).
- 녹화 파일은 run 디렉터리 `capture.webm`로 옮기고 `capture.video`에 기록. 녹화가 실패해도 스크린샷·capture.json은 지금처럼 나온다(`video` 생략).
- 정지 스크린샷(`image`)은 계속 찍는다 — 대체 화면·미리보기 썸네일용.

**마스킹 규칙 (결정됨)** — `capture/AGENTS.md`의 "입력값은 캡처 화면에서 마스킹 처리한다"를 **"auth(로그인) 값은 영상·스크린샷·로그·capture.json 어디에도 남기지 않는다. 일반 단계 입력값은 가리지 않는다"**로 바꾼다. 일반 단계 입력값은 LLM이 만든 데모 문구라 민감하지 않고, 한 글자씩 입력되는 장면이 움직임의 핵심이다. 지금의 `typed` 마스킹(c453c6f)은 일반 단계에서 빼고, 로그인 장면 스크린샷에만 쓴다.

**로그인 장면 (낮은 우선순위 — 녹화·렌더가 끝난 뒤 선택 작업)**
- 녹화하지 않는 로그인 컨텍스트에서 정지 화면 2장을 찍는다: ① 로그인 페이지 도착 직후(빈 입력칸), ② 아이디·비번 입력 후 로그인 버튼을 누르기 직전(입력칸 마스크). `capture.login.images`에 기록.
- 로그인 과정은 녹화 파일에 들어가지 않는다(위 storageState 방식 그대로).

**렌더 (render/)**
- `ScreenScene`: `video`가 있으면 `OffthreadVideo`로 구간 재생(구간과 `durationSec`이 다르면 재생 속도 0.5~2배로 맞추고, 그래도 짧으면 마지막 프레임 정지). 없으면 지금처럼 `image`.
- 브라우저 카드 프레임: 밝은 배경 위에 둥근 모서리 + 그림자 + 상단 주소창 바(도메인 표시) 안에 화면을 넣는다.
- 자막: 하단 좌측 검은 라벨 박스, `highlight` 단어는 주황색.
- `TitleScene`에 `kicker`가 있으면 장 구분 카드(밝은 배경, 작은 번호 + 큰 문장).
- 배경음악: 라이선스 문제없는 짧은 루프 1곡을 render 쪽 정적 파일로 두고, 낮은 볼륨 + 끝 페이드아웃.
- 전체 톤을 밝은 배경으로 통일(지금 남색 타이틀 → 기준 영상처럼 밝은 회백색).
- `render.mjs`/`use-run.mjs`: `capture.webm`이 run 디렉터리와 함께 넘어가는지 확인.

### C — web (이슈로 전달)

- 입력 화면에 **테스트 계정 아이디·비밀번호**(선택) 칸과 **"영상에 바라는 점"** 프롬프트 칸(선택, 500자) 추가 → `POST /api/runs`의 `login`, `prompt`.
- 고급 옵션: 로그인 URL 직접 입력(소셜 로그인만 있는 앱용) → `auth: {steps: [{goto}]}`로 보낸다.
- 비밀번호 칸은 `type=password`, 응답에 돌아오는 값은 `***`.
- 미리보기·수정 화면은 scene의 `video`·`highlight`·`kicker`를 지우지 않고 유지한다.
- 아키텍처 장면이 노드 1개("Flutter")일 때 보기 흉하다 — 노드가 2개 미만이면 장면을 빼거나 서비스 흐름 표로 바꾸는 것을 C가 판단.

## 결정된 것

- 마스킹: "auth 값은 어디에도 남기지 않는다, 일반 입력값은 가리지 않는다"로 바꾼다 (사용자 결정, 2026-11-22).
- 로그인 장면: MVP 제외에서 풀고, 입력칸을 가린 정지 화면으로만, 낮은 우선순위로 넣는다 (사용자 결정).
- 프롬프트가 바꾸는 것: 화면 순서, 자막 말투, 강조할 부분 (사용자 결정).
