# Backend(A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 레포 URL + 배포 URL → 계약을 통과하는 scenario.json / scene.json을 만들고, C의 웹이 쓸 FastAPI로 파이프라인을 묶는다.

**Architecture:** GitHub에서 필요한 파일만 받아(캐시) 정규식으로 라우트·UI 요소를 뽑은 `RepoFacts`를 만든다. LLM은 단순화된 초안 모델만 생성하고, 코드가 이를 계약 JSON으로 변환·검증·근거 필터링한다. 실패 시 항상 규칙 기반 기본값. API는 같은 함수를 BackgroundTasks로 돌린다.

**Tech Stack:** Python 3.12, uv, FastAPI, httpx, pydantic v2, anthropic 2.12 (`messages.parse`), jsonschema, pytest.

**Spec:** `docs/superpowers/specs/2026-11-22-backend-a-design.md`

## Global Constraints

- 모든 명령은 `backend/`에서 `uv run …`. 완료 조건은 루트 `make check` 통과.
- 계약 파일(`contracts/**`, `backend/app/contracts/{scenario,capture,scene}.py`) 수정 금지. 타입은 `from app.contracts import Scenario, Capture, SceneDoc, schema_errors`.
- 모델 `claude-opus-5-5`, `output_config={"effort": "low"}`, `max_tokens=16000`, `client.messages.parse(output_format=<Draft 모델>)`. thinking 파라미터는 보내지 않는다.
- 키는 서버 `.env`(`ANTHROPIC_API_KEY`, `GITHUB_TOKEN`)만. 사용자 키 입력 없음. 키를 로그·파일에 쓰지 않는다.
- 공개 레포만. 로그인 페이지·요청흐름·ERD·자연어 수정 없음.
- 테스트는 네트워크·LLM 없이 돈다: httpx `MockTransport`, LLM은 `LLM` 프로토콜의 가짜 구현.
- 경로: run 디렉터리 `runs/<id>/`(레포 루트 기준), 캐시 `runs/cache/`. 레포 루트는 `app.paths.ROOT`.
- 수치: scenario 5~7단계(기본값은 정적 라우트 최대 6개 goto), 페이지당 요소 15개, LLM 재시도 2회, 받을 파일 최대 80개·파일당 200KB.

## Review Focus

1. 레포 URL 변형(`.git`, 끝 `/`, `/tree/<branch>/…`, `http://`, `www.`) → 같은 owner/repo로 파싱. 깃허브가 아닌 URL은 `RepoError`. → Task 1 테스트
2. React/Next 앱이 없는 레포(Vue·백엔드 전용) → 예외 없이 `routes=[]`, scenario 기본값은 `/` goto 1단계. → Task 3, 5 테스트
3. GitHub 404 / rate limit 403 → 사람이 읽을 수 있는 `RepoError` 메시지("레포를 찾을 수 없음", "GitHub rate limit — GITHUB_TOKEN 설정"). → Task 1 테스트
4. Next 특수 세그먼트: `(group)` 제거, `[id]`/`[...slug]` 동적, `@slot`·`(.)` 인터셉트·`_private` 폴더 제외. → Task 2 테스트
5. LLM이 refusal / 스키마 위반 / 코드에 없는 경로·문구를 반환 → 해당 단계 제거, 남는 게 없으면 기본값. 결과는 항상 `schema_errors == []`. → Task 4, 5 테스트
